# UI redesign scope: match the UAT look (for approval)

Source of truth: `reference/uat/AUDIT.md` section 4 (approved by the user), `reference/uat/tokens.css`, the 22 UAT screenshots. Pilot 2 "before": `reference/pilot2-before/`.

**Rules for the whole job:** plain HTML/CSS/ES modules, no framework, no build step, no new dependency, bundled fonts only (Inter, Manrope; Sora stays for the sign-in page). Nothing is removed. Only screens Pilot 2 already has. Only the look and arrangement change; business logic, API routes and data do not (one exception, see Filter). Each phase ends with before/after screenshots at 1440x900 and 1024 wide, the full test suite (`pytest -q`, 353 now) and an honest entry in `PROGRESS.md`. The built-in browser is used only to look at the local app; the UAT is only looked at, never changed.

## The one non-visual change (needs your OK)
The Filter popover must filter the whole list, not just the page on screen, so each filter needs a small **additive, optional query parameter** on the existing list endpoints (`GET .../requirements`, `.../test-cases`, `.../test-scripts`), e.g. requirements: scanned / not scanned, generated by model, created from/to; test cases: type, requirement, has script / out of date; scripts: language, out of date, last result. Existing calls keep working unchanged; each parameter gets a test. If you prefer a pure-look change, say so and the Filter button is built without filters (search only).

## Explicitly NOT built
Dashboard, Test Batches, Traceability, Knowledge Base, Fleet, Job Monitoring, Integrations, Execution settings, workspaces, rich text editors, quality score / suggestions, KPI cards, charts, Notification Preferences, Roles, Join Requests, Invitations, cookie banner. No UAT data is copied; no UAT screenshot is published. No change to `system-prompts/`, the pilot folders, the API's behaviour, or the runners.
